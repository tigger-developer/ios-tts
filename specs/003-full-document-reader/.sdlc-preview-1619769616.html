Full document reader for macOS and iOS

Outcome
Open the whole current note so Apple's Accessibility Reader can read it on macOS and iOS.
Before
For long documents, Obsidian preview loads only a portion for display, so Accessibility Reader cannot access the whole document. This project has no implemented plugin.
After
A button or command opens one read-only snapshot within the configured limit, rendered in full. The user invokes Accessibility Reader and presses Play.
Changes
Add the reader, settings-panel shortcut help and a saved 100,000-word default limit. Use normal Markdown rendering. README and docs/VISION.md explain the same benefits, limitations and listing intent.
Installation amendment
make install asks for the vault root, then puts the three built files in .obsidian/plugins/ios-tts/. Missing plugin directories are created; settings and unrelated files are preserved. The explicit PLUGIN_DIR route remains available for compatibility.
Unchanged
Obsidian owns rendering; Apple owns speech. The plugin does not edit notes, retain their contents, add network services or control audio.
Edge cases
Handle empty or unsupported notes, rendering errors, repeated invocation and closing during rendering without retaining stale content. Over-limit notes are refused, never truncated. Invalid settings retain the active limit; load failures use the default with a notice and no silent rewrite. Invalid install targets fail before copying; partial-copy errors are reported.
Decisions
Target Obsidian 1.13+, macOS 26+ and iOS 26+. Development stays outside the vault; the operator manages the testing symlink and iOS copy.
Settings
Save only the word-limit preference in Obsidian plugin data. Help covers triple-clicking the side/lock button, double-tap Back Tap, native speech without usage fees, and macOS setup. No system settings change.
Distribution
Prepare Community directory copy and readiness guidance; actual release and listing submission follow operator review.
Evidence
Focused session and word-limit tests, native user tests on both platforms, and bounded package and security checks. Complete native reading of a 100,000-word text note remains unverified until those user tests pass.

Context

Problem and outcome

For long documents, Obsidian preview loads only a portion of the document for display. Accessibility Reader cannot access the unloaded content, so it cannot read the whole document.

The user needs the complete current Markdown note available to native Accessibility Reader, including content beyond the visible viewport. The plugin's responsibility is a full document presentation, not text-to-speech.

Scope

Included
One Open full document reader ribbon button and equivalent command; one scrollable reader; one settings panel containing shortcut help and a maximum-word setting; README, vision and listing preparation.
Content
Pass the entire current Markdown source to Obsidian's public renderer. Preserve its normal body rendering, including links and embeds. Do not synthesize a separate filename title or properties panel, extract media text, expand links independently, or rewrite rendered content.
Excluded
Speech controls, custom Markdown parsing, export, EPUB/PDF conversion, live synchronization, background vault scanning, release publication, marketplace submission and automated vault deployment.
Unchanged
Existing editing, vault settings, other plugins and native accessibility configuration remain under their existing owners.

Compatibility
Support Obsidian 1.13 or later on macOS 26 and iOS 26 or later. The manifest is mobile-compatible. Other operating systems and replacement speech facilities are outside the acceptance claim.
Simplicity
Use standard rendering, one settings panel, bundled help and one saved number. No old special content transformation is retained.
Size
Never truncate. The default maximum is 100,000 words, configurable as a positive whole number. Higher values permit attempts on larger notes; they do not establish a tested capacity or an unlimited resource guarantee. Word count is not a byte or image-memory limit. Conversion and repair of binary or image-heavy imports remain excluded.
Comparison
Explain that some cloud TTS plugins require API keys and paid generation, which can accumulate for long or repeated conversions. Apple devices already provide native speech without a speech API usage bill. Do not imply all other TTS plugins are paid or that cloud voices have no value.
Feasibility
Native discovery of the whole off-screen document is an integration risk. Test the minimal view early during delivery. If the public renderer cannot satisfy it, record the failure and return the specific design decision; do not add extraction engines or weaken completeness silently.

Acceptance Criteria

AC003.1 - Full current-note snapshot

Criterion
For an active Markdown note within the configured word limit in editing or reading mode, the reader button and command present its complete current rendered body in document order, including current editor changes. Empty content is valid. Opening again captures the current note, not the previous snapshot.
Proven by
UT003.1 - macOS reading workflow and UT003.2 - iOS reading workflow.

AC003.2 - Complete native reading

Criterion
On each supported platform, for an accepted note within the configured limit, Accessibility Reader can discover and read the whole rendered document through its final text, without manually scrolling the plugin view to reveal missing text. Plugin controls do not interrupt the document's reading sequence.
Proven by
UT003.1 - macOS reading workflow and UT003.2 - iOS reading workflow.

AC003.3 - Source preservation

Criterion
Reader use provides no editing surface and causes no changes to source notes or their properties, including interaction with rendered task checkboxes. The plugin retains no note contents after the reader closes.
Proven by
UT003.1 - macOS reading workflow, UT003.2 - iOS reading workflow and OT003.1 - Source and security review.

AC003.4 - Single transient reader

Criterion
At most one current reader exists. A later invocation replaces the prior snapshot; closing or disabling the plugin releases its owned view and resources. Late rendering cannot reopen or replace a newer reader.
Proven by
RT003.1 - Reader session lifetime, UT003.1 - macOS reading workflow and UT003.2 - iOS reading workflow.

AC003.5 - Clear unsupported and failed states

Criterion
A missing or non-Markdown active note produces a brief notice requesting a Markdown note. A failed render produces a brief failure notice. Neither outcome shows stale or partially prepared content or alters a note.
Proven by
RT003.1 - Reader session lifetime, UT003.1 - macOS reading workflow and UT003.2 - iOS reading workflow.

AC003.6 - Native speech and existing access boundaries

Criterion
The plugin does not invoke speech, send note content to a service, save note content to storage or logs, or add privileged access or network operations beyond Obsidian's normal rendering of the same note. Presenting local text does not require a network connection, account or API key.
Proven by
OT003.1 - Source and security review and UT003.1 - macOS reading workflow and UT003.2 - iOS reading workflow.

AC003.7 - Platform lifecycle and accessible controls

Criterion
On both supported platforms, enabling the plugin makes its named button and command available without opening a reader or scanning documents at startup. The reader is scrollable and dismissible using the platform's normal pointer, touch or keyboard controls. Disabling and enabling again leaves one set of controls and Obsidian usable.
Proven by
UT003.1 - macOS reading workflow, UT003.2 - iOS reading workflow and OT003.1 - Source and security review.

AC003.8 - Brief usable instructions

Criterion
The README identifies supported platforms, installation files and the open reader, invoke Accessibility Reader, Play flow, with links to Apple's setup instructions. The plugin settings panel contains bundled setup instructions and benefits/limitations, including triple-clicking the side/lock button, the Home-button alternative, double-tap Back Tap through Accessibility Shortcut, and the Mac shortcut. It explains native speech ownership, cloud-TTS costs, the word limit and normal-rendering boundary. README and docs/VISION.md present consistent claims and listing intent. Help remains readable offline; following an external link is optional.
Proven by
UT003.1 - macOS reading workflow and UT003.2 - iOS reading workflow.

AC003.9 - Installable package and explicit destination

Criterion
The locked build produces main.js, manifest.json and styles.css for both supported platforms. Local installation writes only those three files into the explicitly supplied destination, preserves other files and skips copying artefacts whose contents already match. Invalid destinations fail before installation writes; an incomplete copy is reported as failure, never success.
Vault-root flow
Plain make install prompts for the Obsidian vault root and installs to its .obsidian/plugins/ios-tts/ directory, creating missing plugins/ and ios-tts/ directories. The root and its .obsidian/ directory must already exist. Blank input, EOF/cancellation and invalid roots produce an actionable non-zero failure without destination writes. Existing symlinks below the root are refused without replacement. Explicit PLUGIN_DIR continues to select the former non-interactive existing-directory route.
Proven by
OT003.2 - Build and local installation.

AC003.10 - Configurable maximum words

Criterion
Settings expose Maximum words, initially 100,000, and Save. A valid saved positive whole number persists across plugin reloads and applies to the next reader invocation. Invalid input or a failed save shows an actionable error and retains the active value. Missing settings use the default; malformed settings or a failed load use it with a notice, without silently overwriting stored data. Saving changes only this preference.
Proven by
RT003.2 - Word limit and preference, UT003.1 - macOS reading workflow, UT003.2 - iOS reading workflow and OT003.1 - Source and security review.

AC003.11 - Explicit refusal above the word limit

Criterion
A note at or below the configured limit remains eligible for complete rendering. A note above it clears any previous reader and receives a notice identifying the limit and explaining how to raise it in settings. It is not rendered or truncated. The check uses the full current Markdown source, counting each whitespace-separated non-empty token as one word; properties and markup count, and empty source counts as zero.
Proven by
RT003.2 - Word limit and preference, UT003.1 - macOS reading workflow and UT003.2 - iOS reading workflow.

Test Definitions

RT003.1 - Reader session lifetime

Covers
AC003.4 - Single transient reader and AC003.5 - Clear unsupported and failed states.
Boundary
The plugin-owned session helper's open and close operations.
Procedure
Use controlled render promises and observable presentation, notice and cleanup callbacks. Exercise success; A then B with A finishing last; close during preparation; rejection; and an invalid invocation after success. Assert the currently visible result, notice and released resources.
Expected
Only the newest valid result appears. Close releases the session; invalid input and rejection clear old content and report the correct failure category. Superseded results and errors do not disturb a new session.
Retention
One small test file using Node's built-in test runner under make test. It tests owned asynchronous state, not Apple's reader or a fake Markdown engine. Automated implementation starts with its expected RED.

RT003.2 - Word limit and preference

Covers
AC003.10 - Configurable maximum words and AC003.11 - Explicit refusal above the word limit.
Boundary
Owned preference load/save and reader admission, with host persistence and rendering supplied as narrow callbacks.
Procedure
Exercise absent, valid, malformed and rejected loads; save a valid value and reload it; reject blank, zero, negative, fractional, nonnumeric and unsafe-integer input; force a rejected save. Observe the active value, stored preference and error category. A pending save blocks a second save; the old value remains active until success. An already-open snapshot remains unchanged, while the next invocation uses the saved value.
Limit cases
Exercise empty and whitespace-only source, mixed whitespace, frontmatter/markup tokens, limit minus one, exact limit and limit plus one. Above the limit, assert no render and no previous presentation; increasing the limit admits the same complete source. Include the 100,000-word default.
Expected
Valid preferences persist; invalid or failed operations never replace the active value or silently rewrite storage. Admission implements AC003.11 - Explicit refusal above the word limit exactly.
Retention
A second small Node test file under make test, written first with its expected RED. It protects limit decisions and persistence failures; it does not simulate settings widgets, Apple shortcuts or the Markdown engine.

Edge Cases

Empty or frontmatter-only
Use the renderer's normal output; do not invent body text or show a previous note. See AC003.1 - Full current-note snapshot.
No valid note or render failure
Clear the previous presentation and report a brief notice. See AC003.5 - Clear unsupported and failed states.
Oversized note
Refuse before rendering and explain the setting; never publish a partial note. See AC003.11 - Explicit refusal above the word limit.
Invalid or unavailable settings
Keep the active limit on invalid input or save failure. Use the default with a notice for malformed data or load failure. See AC003.10 - Configurable maximum words.
Reopen, close or disable during preparation
Discard stale results and release resources. See AC003.4 - Single transient reader.
Invalid installation target or copy failure
Fail explicitly under the installation contract. See AC003.9 - Installable package and explicit destination.
Rich content and large imports
Keep normal rendering behaviour; do not add conversion, image extraction or recursive loading. Full-document success is required for the specified fixtures, not arbitrarily large binary imports. See AC003.1 - Full current-note snapshot and AC003.2 - Complete native reading.

Solution Design

Architecture and flow

  1. Load and validate the word-limit preference, then register the ribbon button, command and settings tab through Obsidian's Plugin API. Perform no document work during plugin startup.
  2. Capture the active MarkdownView, its file path and getViewData() once before asynchronous work. Validate a present Markdown file; do not read a disk copy in place of current editor contents. Capture the current saved limit too. Clear the prior session and check the source word count before rendering; over-limit input receives the settings guidance notice.
  3. Close the previous reader and open a dismissible Obsidian Modal with a preparing notice. Render the whole captured source into one detached article using MarkdownRenderer.render and a session-owned Component. Pass the captured source path for normal relative references.
  4. After rendering succeeds, replace the preparing notice with the complete, scrollable article. Do not use preview sections, virtualization, folding or lazy body rendering. Keep the close control outside the article. Disable task editing controls without hiding the article from accessibility.
  5. The user invokes Apple's Accessibility Reader. Closing, replacing or unloading invalidates the session, detaches the article and unloads its component. Late success or failure cannot publish into a later session.

Interfaces and state

Structure
Start with src/main.ts for host integration, settings UI and the modal; src/reader-session.ts for asynchronous lifetime; src/reader-settings.ts for preference validation and word-limit admission; and styles.css. No content-normalization framework or six-module architecture.
Language
Strict TypeScript compiled to a CommonJS Obsidian bundle, targeting ECMAScript 2022. Node and npm are development tooling only; no Node or Electron calls and no added runtime library in the plugin.
Build
Use the ordinary Obsidian TypeScript/esbuild toolchain. Delivery pins current compatible development versions and one npm lockfile. Provide make build, make lint, make test, make vulncheck, make install and make sync with their SDLC meanings; do not add a deployment service.
Package
main.js, manifest.json and styles.css form the plugin. Use manifest identifier ios-tts, minAppVersion: 1.13.0 and isDesktopOnly: false. README documents the additional OS requirements.
Installation
make install builds, then runs scripts/install.mjs. Unless PLUGIN_DIR is non-empty, prompt for the vault root, trim the input, allow optional matching surrounding quotes and expand leading ~/ using the platform home-directory API. Require an absolute existing directory and resolve that explicitly selected root canonically. Require an existing real .obsidian/ directory. Reject symlinks or non-directories at .obsidian, plugins and ios-tts before creating missing plugin directories. These child names are fixed; no vault search or shell evaluation is used. Blank input, EOF and Ctrl-C abort. Readline is closed on every exit.
Compatibility
make install PLUGIN_DIR=/absolute/plugin/directory keeps its non-interactive explicit existing-directory semantics, including a directory symlink that the operator explicitly supplied. This route does not prompt or create directories. Both modes validate all artefacts before any copy: each must be absent or a regular file, never a symlink or directory. Fixed artefact basenames stay within that canonical destination; no recursive copy is allowed. The prompt route creates missing directories only after validation. Report the installed destination and remind the user to enable the plugin in Obsidian. Print the disabled-plugin prerequisite before prompting.
Replacement
Replace only changed artefacts and preserve all other files. Installation requires the plugin disabled. Individual copies are not a transaction: an I/O error exits non-zero, reports possible partial installation and directs a retry before re-enabling. Do not replace or remove the whole destination directory. The copy step leaves identical files untouched; rebuilding may regenerate the checkout's own build outputs.
Symlink workflow
If the canonical destination is the checkout itself, the build already publishes the artefacts through the operator's symlink; verify the three files and skip copying. iOS receives the same files through the operator's existing process. Never edit the enabled-plugin list.
Settings
Use Obsidian's PluginSettingTab and Setting controls for one Maximum words field and Save. Accept trimmed decimal digits representing a positive safe integer; reject other input rather than coercing it. Use loadData() and saveData() for { maxWords: 100000 }; persist no note data. Disable Save while a write is pending and update the active limit only after success. On failure retain it and show a retryable error. A missing setting defaults normally; malformed data or a rejected read defaults with a notice and no write until an explicit valid Save. Use host-managed storage only. Ignore its data.json in Git during symlink testing; installation preserves it.
Admission
Count non-empty whitespace-delimited tokens in captured Markdown source, including properties and markup. A linear scan may stop as soon as it exceeds the captured limit. Do not allocate a second whole-document token array or expand embeds just to count. Invalid/over-limit input clears the previous reader without invoking the renderer.
Help
Bundle docs/reader-help.md into main.js as a static text import; render it with the host renderer in the settings tab and clean up its owned component on hide/unload. No runtime fetch, images or embedded resources in help. Its external links open only on user action. Keep the maintained text in the document, not a second copy embedded in TypeScript.
State
Retain captured source, render component and modal only for their session lifetime. The sole durable state is the word-limit preference; no database, note-content storage or migration is introduced.
Failure
Release the current failed session and show a short Obsidian Notice without note text, file paths or raw exceptions. Missing or unsupported input says to open a Markdown note; rendering failure says the reader could not open it. Over-limit input identifies the maximum and says to increase Maximum words in plugin settings. Exact wording and documentation brevity receive human review, not string-matching tests. No automatic retries.

Security impact

Threat boundary
Note content enters Obsidian's existing Markdown renderer. Do not insert untrusted HTML manually or add executable processors.
Existing rendering
Normal embeds, remote resources and installed Markdown processors remain host behaviour. This plugin is not a sandbox and does not promise that arbitrary third-party rendering is offline or read-only. The supported user-test baseline uses only core plugins and local fixtures.
Data and access
The plugin adds no external service, content logging, durable content storage, credentials or privileged host API. Do not change the user's system settings or vault permissions. Save only the validated word-limit number through Obsidian's plugin storage. The word limit reduces oversized-text rendering attempts; it is not a byte-size limit or a defence against arbitrary embedded content.
Dependencies
make vulncheck uses npm's non-mutating locked dependency audit, including build dependencies. It remains separate from make test; failure or an unavailable scanner blocks its result. Use the standard gate directly, without a new exception-management framework.

Other relevant qualities

Accessibility
Inherit Obsidian's theme and modal focus/dismissal behaviour. Use semantic document markup and accessible names; verify native reading on both platforms instead of inferring it from the DOM.
Performance
Render only on invocation, once per snapshot. Avoid deliberate truncation and background work. Record observed long-note responsiveness; do not resurrect the old five-second or exact-action-count targets.
Maintainability
Reuse public host APIs. The only retained automated test areas are owned asynchronous session state and word-limit preferences. Human tests cover settings help, rendering, native discovery and interaction; do not add browser automation or a mock host.
Rollback
Disable the plugin and remove its installed artefacts or testing symlink. Its saved word-limit preference may remain in host-managed plugin data; no source-note migration or recovery operation is required.
