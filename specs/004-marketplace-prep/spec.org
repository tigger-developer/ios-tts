- Proportionality :: GitHub orchestration and short shell steps suffice; no packaging framework, dependency installation or plugin build is introduced. The existing offline reader tests remain unchanged. Hosted publication/attestation is a production operation, not a metered regression suite.

* Operator-invoked release amendment, 2026-09-16

- Approval :: Operator-invoked releases approved 2026-09-16. =make release= owns publication; pushing to master no longer publishes a release.
- Supersedes :: The push-triggered release job of the *Automatic patch-release amendment*. Releases 1.0.0 to 1.0.4 remain historical evidence of that process. Runtime behaviour, the patch-increment scheme and the three-file release inventory are unchanged.
- Scope :: Add =scripts/release.sh= and a =make release= target that publishes one release from =master=. Remove =.github/workflows/release.yml=. Trigger =.github/workflows/attest-release.yml= on release publication, retaining manual dispatch for recovery. No reader feature, dependency, build step or credential is added.
- Design :: =make release= runs =make lint= and =make test=, then =scripts/release.sh=. The script validates its invocation, requires =git=, =jq=, =gh= and =trash=, and refuses to continue unless the current branch is =master=, the working tree is clean and the local branch equals =origin/master=. It selects the next patch version from the manifest, or the exact =VERSION= when supplied, and refuses a tag that already exists locally or on the remote. It rewrites =manifest.json= and the =main.js= version comment through temporary files beside their targets, commits both as =chore: release <version>=, creates an annotated tag, pushes commit and tag atomically, then creates the GitHub release with =main.js=, =manifest.json= and =styles.css= and generated notes. =--dry-run= reports the version and attachments without changing the repository or the remote; =--help= and =--version= exit successfully without side effects.
- Attestation :: The attestation job is unchanged in what it verifies and signs. Its trigger becomes =release: published= with =workflow_dispatch= recovery, and its tag comes from =github.event.release.tag_name= or the dispatch input. It also asserts that the release inventory is exactly the three installation files. Concurrent runs queue without cancelling an active signing run.
- Concurrency and recovery :: A competing push makes the atomic push fail visibly; no force push or automatic conflict resolution is performed. When the push succeeds but release creation fails, the published tag is reused through =gh release create= rather than retagging. A release created by any other route also triggers attestation, which is intended. Release 1.0.4 was published by the superseded process before this change and carries no attestation from it; manual dispatch can sign it.
- Security :: No workflow retains =contents: write=. Publication uses the operator's authenticated =gh= and the configured SSH remote, so an automated push can no longer create a release. The attestation job retains =contents: read=, =id-token: write= and =attestations: write=, without persisted checkout credentials. Actions remain pinned to verified upstream commit hashes.
- Documentation :: =docs/release-help.md= documents the target, options and recovery. =docs/releases/automation.md= describes the operator-invoked release and the publication-triggered attestation, and identifies the superseded push-triggered process. The developer target list records =make release=.
- Proportionality :: One short shell script and one trigger change are sufficient. No packaging framework, release service or persistent source-text test is introduced.
